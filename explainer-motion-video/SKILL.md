# 사내 설명용 모션그래픽 영상 (가로 1920×1080)

반대 집단·경영층·개발자 같은 **설득이 필요한 사내 청중**에게 전략과 변화를 설명하는 5~8분짜리 가로 영상을 만든다.
'IT 회사의 길' 시리즈(본편 v6~v8, 온톨로지 편, 속도 편)를 만들며 사용자와 맞춰 온 규칙을 모두 담았다.
세로 쇼츠는 `shorts-video-studio`를 쓴다.

엔진·도구·예제는 GitHub `bitlife70/skills` 저장소의 `explainer-motion-video/` 폴더에 있다(1절).

---

## 0. 작업 흐름 (이 순서를 지킨다)

1. **스토리 초안을 채팅으로 먼저 보여 준다** — 컨셉, 한 줄 메시지, 설득 장치, 막별 내레이션(번호 붙인 문장), 장면 구상 요약, 확인할 점.
2. **사실 검증** — 주장마다 근거를 찾고(웹 검색), 근거가 강하면 그대로, 약하면 맥락만 전달되게 다듬는다. 검증표(주장 · 판단 · 영상에서의 처리)와 출처를 함께 보여 준다(2절).
3. 사용자 피드백 반영 → 스토리 재작성(바뀐 줄은 (신규)/(수정) 표시).
4. **대표 장면 3~5장을 먼저 캡처해 승인받는다** — 풀 제작 전에 디자인·구성 확인. 승인 전엔 내레이션을 녹음하지 않아도 된다(임시 타이밍으로 스틸 가능).
5. 승인되면 풀 제작: 내레이션 녹음 → 타이밍 → 전 장면 구현 → **자동 선 검증** → 전 장면 스틸 육안 점검 → 렌더 → 음성·자막 합성 → 전달.
6. 사용자가 **타임코드별 수정사항**을 주면 해당 장면만 고치고, 바뀐 문장만 재녹음, 바뀐 장면만 재렌더해 `_v2`로 전달한다.
7. 요청 시 유튜브 설명란 + 썸네일 2종(9절).

진행이 길면 TaskCreate로 단계(스크립트·녹음 / 장면·검증 / 렌더·전달)를 만들고 체크한다.

## 2. 스토리와 설득 (내용이 먼저다)

**청중 진단 먼저.** 반발심·관성(개발자, 기존 방식에 익숙한 조직)인지, 불신·정밀 검토(경영층)인지 본다.
반발심·관성엔 압박 대신 공감·선택권·작은 첫걸음, 불신엔 근거를 쌓는다. `persuasion-playbook` 메모리가 있으면 참조한다.

검증된 막 구조(속도 편 기준, 7분 안팎 · 45문장 내외):
1. **프롤로그 — 실제 목소리로 훅**: 고객·현장에서 들은 말(Pre-Suasion). 청중이 할 반론을 먼저 인정("그 감각은 틀리지 않았다").
2. **저쪽 세계의 증거**: 프론티어 기업·스타트업·실제 사건의 숫자(사회적 증거·권위).
3. **청중의 망설임을 존중**: 게을러서가 아니라 책임감·자부심 때문이라고 말한다. 비난하지 않는다.
4. **갈라지는 회사들**: '도태'는 회사 일반에게만. 개인을 향하지 않는다.
5. **방식의 전환**: 무엇이 어떻게 바뀌는지(가능하면 최신 방법론·실제 사례·시간 축).
6. **확장·실제 사례**: 국내 사례 + 해외 사례를 짝지어 "이상이 아니라 현실"로.
7. **우리의 전략·플랫폼**: 청중의 자리가 **한 단계 올라간다**는 프레임(손실 회피 + 성장).
8. **맺음**: 거창하지 않은 첫걸음 + 기억에 남는 한 문장(큰 글자, 자막 없음).

**사실 검증 규칙**
- 현재 상태를 말하는 모든 숫자·사례는 검색해 확인한다. 날짜·주체·조건(프로덕션 vs 실험, 원형 vs 완성품, 사람 승인 여부)을 정확히 쓴다.
- 근거가 약하면 수치를 빼고 맥락만("코딩 경험 없는 사람이 앱을 만드는 일이 흔해졌다"). 과장된 수치(예: 출처 스스로 과장이라 한 것)는 쓰지 않는다 — 개발자 청중은 과장을 바로 알아챈다.
- 반론이 있는 주장은 양면으로("사람 눈으로는 서너 개가 한계 → 그래서 감독을 하네스에 맡긴다")해서 오히려 논리를 강화한다.
- "모두가 ~한다" 같은 전칭은 "크든 작든 많은 ~"로 누그러뜨린다.
- 출처는 채팅 답변 끝에 Sources로, 유튜브 설명란에 참고 자료로 남긴다.

**민감도**
- 고객사 실명·내부 전략(경쟁 솔루션, 인력 관련 언급)이 들어가면 사내용임을 알리고, 외부 공개 시 일반 표현 버전을 제안한다. 고객을 함부로 실명 거론하지 않는다.
- 실존 브랜드는 텍스트로만(로고 없음). 플랫폼 기업을 비교할 땐 'AI 플랫폼 A/B/C'처럼 일반화.

**대본 문장 규칙**
- 한 문장 = 한 줄(line). 막당 2~6문장. 긴 문장은 쉼표로 숨 쉴 자리를 둔다.
- 영어 약어·숫자는 녹음용 발음 표기(`tts`)를 따로 둔다(3절). 화면 자막(`sub`)은 원문 그대로.

## 3. 내레이션 (Typecast 필재)

- 도구: `mcp__remote-devices__typecast__text_to_speech` (타임스탬프 버전은 출력이 너무 커서 쓰지 않는다)
- `voice_id: tc_68257f68bc6e3c161ab5078d`, `audio_tempo: 1.1`, `model: ssfm-v30`. **BGM은 쓰지 않는다.**
- 한 번에 10개 안팎씩 **순서대로** 호출한다(파일명이 타임스탬프 순 = 문장 순). 같은 문장을 다시 녹음하지 않는다.
- 발음 표기 예: AI→에이아이, IT→아이티, MCP→엠씨피, FDE→에프디이, SI→에스아이, ERP→이알피, MES→엠이에스, BA→비에이, OS→오에스, API→에이피아이, SDK→에스디케이, AWS→에이더블유에스, AX→에이엑스, 오픈AI→오픈에이아이, Claude→클로드, Claude Code→클로드 코드, Cowork→코워크, C 컴파일러→씨 컴파일러. 큰 숫자+단위는 한글로(150개→백오십 개, 1,500건→천오백 건). 따옴표는 뺀다.
- 파일은 사용자 PC `C:\Users\User\workspace\typecast_output\`에 저장된다. 가져오기:
  1. `device_bash`: `cd "$HOME/mnt"; D=motion_graphic_playground/<프로젝트>; mkdir -p $D/voice_<편> $D/_scratch; i=1; for f in $(ls typecast_output/<날짜-시각 접두>*.wav | sort); do cp "$f" $D/voice_<편>/p$(printf %02d $i).wav; i=$((i+1)); done; cd $D && tar cf _scratch/voice_<편>.tar voice_<편>`
  2. `device_stage_files`로 tar를 올리고 → 작업공간에서 `tar xf /mnt/user-data/uploads/.../voice_<편>.tar`
- 수정 녹음은 `q01, q02…`처럼 접두를 바꿔 같은 폴더에 둔다. `lines.json`의 `file`로 줄마다 어떤 파일을 쓸지 지정하므로 나머지는 재녹음하지 않는다.

`lines.json` 형식: `[{"n":1,"scene":"P1","sub":"자막 원문","tts":"발음 표기","file":"voice_x/p01.wav"}, …]`

## 4. 타이밍 (`tools/build_timing.py`)

- 음성 시작·끝은 진폭이 최대치의 2%를 넘는 지점으로 잡는다. `LEAD 0.7 / GAP 0.45 / TAIL 1.3`초.
- 막이 끝나는 줄 뒤엔 `EXTRA`로 0.3~0.5초 숨을 둔다. 타이틀은 무음 6.5초(`TITLE`).
- 자막은 ≤30자로 구두점에서 나누고, 시간은 글자 수 비례로 배분한다. `HL` 키워드는 `*강조*`로 파란색.
- **어색한 분절은 `OVR`로 직접 끊는다** — "100만 / 줄짜리", "만질 / 수 있는", "눈이 / 아니라", "수천, / 수만"처럼 숫자·관형구가 갈리면 반드시 고친다(합치면 원문과 같아야 함 — 스크립트가 검사).
- 결과: `src/timing.js`(TM) + `timing.json`. 장면 안의 줄 시작 시각이 `L[i]`(장면 기준 초)로 장면 함수에 들어간다.

## 5. 디자인 규칙 (사용자 승인된 톤)

- **가로 1920×1080, 30fps만.** 세로 금지.
- 다크 남색 배경 + **파랑이 메인**인 파스텔 팔레트(core.js `C`: bg #0F1522, blue #8AB8FF, sky, mint, lav, peach, butter, rose, gray). **그래디언트 최소화**, 단순한 플랫 도형.
- **슬라이드처럼 만들지 않는다.** 오브젝트·도형·일러스트가 주인공이고, 글자는 설명용. 스토리를 풀 땐 사람·로봇·건물·서버·문서·달력·지구 같은 형상으로 직관적으로 보여 주고, 구조 설명이 필요할 때만 박스와 선(시스템 구성도)을 쓴다 — 구성도는 전문적으로 보이는 장점이 있다.
- **글자는 멀리서도 보이게**: `FONT_SCALE 1.22`(자막 ≈41px, 장면 제목 ≈41px), 화면 안 설명 글자는 실제 22~24px 이상(코드 size ≥ 18~20). 작은 꼬리표도 18 이상.
- 화면 구성: 왼쪽 위 장(막) 라벨 + 제목(`header`), 아래 자막 영역(y ≥ 930 비움), 맨 아래 진행바(타이틀 제외).
- 타이틀 장면: 작은 시리즈 라벨 → 큰 2줄 제목(둘째 줄 파랑) → 부제, 오른쪽에 상징 일러스트.
- 맺음: 마지막 1~2문장은 화면 중앙 큰 글자, 자막은 숨김(`window.NOSUB_LAST`).
- 비교는 좌우 분할(왼쪽 회색 '지금까지' / 오른쪽 파랑 '이제'), 과정은 순환 고리, 성장은 막대·계단, 규모는 점·미니봇 군집, 시간은 로그 시간축·달력이 잘 먹혔다.
- 같은 요소가 계속 설명되며 채워질 땐 **점선 윤곽을 유지한 채 하나씩 채운다**(사라지지 않게).
- 장면 전환은 0.45초 페이드. 한 장면 안의 단계 전환은 `beat()`로 — **나가는 것이 끝난 뒤 들어오게**(동시에 겹치면 검증기가 겹침으로 잡는다).

## 6. 장면 코딩 규칙 (`src/scenes.js`)

```js
function P4(R, t, L) {                     // R: 검증용 레지스트리, t: 장면 내 시간(초), L: 줄 시작 시각들
  header(CH4, 'AI를 조수로 쓰나, 목표를 맡기나', t);
  const a1 = ap(t, L[1], .6);              // ap(t, 시작, 길이) = 0→1 진행도, beat(t, a, b, fi, fo) = 나타났다 사라짐
  person(330, 720, 1.5, C.peach, { a: a1 });                         // 일러스트(art.js / helpers.js)
  box(R, 'goal', 1030, 300, 300, 84, { label: '목표 · 기준', col: C.butter, a: a1, fillA: .2, lsize: 26 });
  box(R, 'ag', 1500, 300, 320, 84, { label: 'AI 에이전트', col: C.sky, a: a1 });
  link(R, 'goal', 'ag', { p: a1, col: C.butter, label: '맡긴다', lsize: 19, lcol: C.text });   // fs/ts: 'l','r','t','b', ff/tf: 변 위치 0~1, mx/my: 꺾임
  if (a1 > 0) caption(R, 'cap1', 330, 800, '결국 *사람이 병목*', { align: 'center', size: 28, color: C.text, hl: C.rose, a: a1 });
}
window.SCENE_FNS = { P0, P1, P4 /* … */ };
```
- 프레임은 **t의 순수 함수**(상태 저장 금지). 같은 t는 항상 같은 그림.
- 선이 닿을 수 있는 모든 것은 레지스트리에 올린다: `box`(자동), 일러스트 위치는 `reg(R,id,x,y,w,h)`, 설명 글은 `caption`(kind 'cap'), 말풍선 `bubble`.
- 선은 `link`(박스↔박스, 화살표), `leader`(화살표 없는 지시선), `line`(자유선; 장식은 `free:true`).
- **캡션·박스는 a > 0일 때만 호출**한다 — 투명해도 등록되면 겹침 오검출. 크로스페이드 사이엔 0.1~0.2초 간격.
- 화면 밖으로 나갈 박스는 그리지 않는다(가장자리 40px 검사). 움직이는 박스는 경로상 다른 박스와 겹치지 않게(먼저 세로, 다음 가로로 이동 등).
- 이름 충돌 주의: 장(막) 상수(`CHP4`)와 장면 함수(`P4C`) 이름이 같으면 스크립트 전체가 죽는다.
- 박스 라벨 글자 넘침은 검증기가 잡는다 → 박스를 넓히거나 `lsize`를 줄인다. `card()`처럼 직접 그리는 텍스트는 `b.textW`를 설정해 검사에 포함시킨다.

## 7. 검증 (선이 도형을 가로막거나 엉뚱한 방향으로 가지 않게)

```bash
SRC=src node tools/check.mjs verify                       # 0.25초 간격 전 장면 검사 → 'VERIFY OK'가 나올 때까지 고친다
SRC=src ONLY=P3,P4 node tools/check.mjs verify            # 일부 장면만

```
검사 항목: 선분↔도형 교차(Liang–Barsky), 선↔선 교차, 화살표 방향, 박스 글자 넘침, 노드 겹침, 지시선↔도형 거리, 자막 영역 침범(y ≥ 930), 화면 가장자리.

**검증기가 못 잡는 것 — 스틸로 눈으로 확인한다**: 장식선(free)이 글자 위를 지남, 등록 안 된 일러스트끼리 겹침, 큰 원·호가 글자를 가림, 반쯤 만들다 만 듯한 배치, 빈 화면(줄이 바뀌는데 그림 변화 없음), 글자 크기. 줄마다 끝나기 직전 시점(`L[i] + 0.8×길이`)을 전 장면 스틸로 찍어 6장씩 이어 붙여 본다.

## 8. 렌더·합성·전달

```bash
# 3개 병렬 렌더 (장면 길이 합이 비슷하게 나눈다). 이미 있는 장면 파일은 건너뛴다 → 수정 시 바뀐 장면 mp4만 지우고 다시 돌린다
for w in "0 P2,P5,P7" "1 P3B,P1" "2 P3,P7B,P4C"; do set -- $w; SRC=src P=$1 ONLY=$2 OUT=_scenes nohup node tools/render.mjs > _scenes/log$1.txt 2>&1 & done
NOSUB_LAST=2 python3 tools/mix.py "시리즈_편이름_가로_1920x1080.mp4" "시리즈_편이름_자막.srt"
```
- 음성: 44.1kHz 믹스 → highpass 70Hz + loudnorm(I −16, TP −1.5, LRA 11) → 48kHz 스테레오 AAC 192k. 자막은 영상에 번인 + SRT 별도.
- 완성 후 프레임 몇 장(`ffmpeg -ss`)을 뽑아 음성·자막 싱크를 확인한다.
- **전달**:
  - `SendUserFile`로 영상 전송(반환되는 `file_uuid` 보관).
  - PC 저장: `device_commit_files`에 큰 mp4는 **`fileUuid`로**(stagedPath는 mp4에서 실패함), 작은 파일(SRT·README·소스 tgz)은 `/mnt/user-data/outputs/<편>/`에 복사 후 `stagedPath`로.
  - 위치: `C:\Users\User\workspace\motion_graphic_playground\<프로젝트>\<편>\` — 영상, SRT, README(장면표·변경 이력·출처), `src_<편>.tgz`.
  - 수정판은 `_v2`처럼 버전을 붙이고 이전 판은 지우지 않는다(PC는 삭제 권한이 기본 꺼져 있음).
- 마무리 답변: 무엇이 나왔는지 + 주요 장면/변경점 요약 + 민감 정보 주의. 과정 나열은 하지 않는다.

## 10. 사용자 피드백에서 배운 것 (반복하지 말 것)

- 글자·박스 위주 장면 → "슬라이드 같다" 지적. 형상으로 바꿔 머리에 남게.
- 비교 장면은 정확한 실제 흐름을 반영(예: "사람이 작성 후 AI가 다듬기"가 아니라 "사람이 짜고 AI는 조수 → 사람이 병목").
- 한 박스에서 여러 층으로 가는 구조는 **모두 연결**(하나만 연결하면 의도를 묻는다).
- 숫자 시간 표현은 현실적으로: 간단한 시스템은 몇 시간, 플랫폼급은 며칠~몇 주.
- 방법론·트렌드는 최신인지 확인(예: SDD·슈퍼파워 → 하네스 엔지니어링(2026.2) → 루프 엔지니어링(2026.6)).
- 청중이 고객과 비교당한다는 압박은 '고객 혼자의 생각'이 아니라 **경쟁사 비교**까지 보여 준다.
- 개발자 대상: "용역형" 같은 말 대신 "요구받은 화면·기능을 구현하던 일 → 에이전틱 AI 핵심 기술(에이전트 설계·오케스트레이션, 하네스·평가, 컨텍스트 엔지니어링, 온톨로지·MCP 연동)로 한 단계 올라간다".
- 실제 사례는 국내 + 해외를 짝지어 넣으면 "이상이 아니라 현실"로 받아들인다.
